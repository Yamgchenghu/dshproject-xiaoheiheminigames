# 背景音乐（BGM）

`public/bgm/` 下的曲目**全部由本仓库的代码从零生成**：

```
编曲模块（JS 数据） → 标准 MIDI（.mid） → 自写 PCM 合成器（.wav） → lamejs 编码（.mp3）
```

没有采样素材、没有音源库、没有下载任何第三方音频。所有音符、节奏、音色、混响
都是 `tools/` 下的脚本现算出来的，因此**不存在任何版权问题**，可以随小程序自由分发。

> **为什么 `public/bgm/midi/` 不能提交**
> `hb-sdk remote deploy` 上传时，服务端 CDN 对 `.mid` 扩展名直接返回
> **「错误的文件路径」**，整个上传在第 3 批就中断（`.mp3` 都过了，只有 `.mid` 被拒）。
> 运行时 `src/core/audio.js` 只拼 `bgm/<name>.mp3`，`.mid` 从头到尾没有任何引用，
> 属于纯死重。需要乐谱源时跑 `node tools/gen-bgm.mjs` 会重新生成，
> 但**提交前记得删掉**，否则提审会被 CDN 拒。

## 曲风从哪里来

用户给了他自己调了几十遍的参考曲《Boarding Pass in the Clouds》
（`ai音乐/_10plus.mid`，9 分 16 秒，17 轨，G 大调音阶但主音是 D）。
他说这个曲风非常喜欢，要求把另外几首也写成同一个味道。

「像不像」不是形容词，我把它测量成可量化的硬指标：

| 特征 | 参考曲实测 | 意味着什么 |
| --- | --- | --- |
| 调式 | **D 混合利底亚** | 有降七级（F 自然音），不是自然大调的 F# |
| 旋律音程 | 三度 **47%** / 二度 29% / 同音 13% / 大跳 7.5% | 以三度为核心的级进线条 |
| 旋律密度 | **5.09 音/小节** | 密集的 4 分音符，不是长音吟唱 |
| 钢琴节奏 | 8.7 音/小节，8 分格 `0/2/4/6/10/12` | 分解和弦铺底 |
| 马林巴 | 480 音，**100% 落在 16 分反拍** `{2,6,10,14}` | 固定的反拍点缀 |
| 打击 | 闭镲 960 / 底鼓 400 / **军鼓仅 40** | 几乎没有军鼓，不用鼓组推节奏 |
| 弦乐 | 3.4 音/小节，一小节一个长音 | 铺底，不做旋律 |

这些数字就是「曲风」本身。任何一条被改掉，听感立刻变味，
而这种退化在代码审查时根本看不出来——所以钉成了 `tools/test-bgm.mjs` 的断言。

### 风格内核

`tools/lib/songs.mjs` 里有一组函数，专门用来复现这个曲风：

| 函数 | 作用 |
| --- | --- |
| `mixo(root, deg, octave)` | 混合利底亚音阶取音 |
| `stepwise(startDeg, steps, opts)` | 级进旋律，三度权重 48%、二度 26% |
| `melodyBar(startDeg, rnd, opts)` | 生成一小节的旋律（6 种节奏型，都恰好 4 拍） |
| `brokenChord(...)` | 8 分分解和弦，`[0,1,2,1,0,1,2,1]`，正拍 52 / 反拍 38 |
| `offbeatMarimba(...)` | 4 个音全部落在反拍 |
| `softPercussion(...)` | 闭镲每拍 + 25% 反拍，底鼓第 1 拍 + 45% 第 3 拍，**无军鼓** |

改曲风只需要改这几个函数，六首曲子会一起跟着变——这是把它们抽出来的理由。

### 各曲的差异

六首必须听起来不是同一首，所以调性、速度、配器各不相同：

- **扫雷** 80 BPM / A — 八音盒主音，悬疑但不压抑
- **2048** 88 BPM / D — 加了向上的竖琴琶音（每 2 小节 4 个音）
- **合成大西瓜** 76 BPM / F — 最慢，稀疏的钟琴代替马林巴，只有闭镲没有底鼓
- **东海龙珠** 84 BPM / C — 加了高频「灯光」铃音（每 4 小节 2 个），贝斯每拍一次（推币的脉冲感）
- **流水入杯** 72 BPM / 降B — 每小节 3 个轻拨弦「滴水音」，这是水声的听觉化

## 循环说明

所有曲目都是**为无缝循环写的**：

- 长度严格等于整数个小节（`小节数 × 每小节拍数 × 60 / BPM`），首尾天然对齐；
- 结尾**没有淡出**，最后一小节的能量与中段持平，接回开头不会掉音量；
- 渲染时多算一小段「尾巴」（混响 / 延迟的余响），再把这段尾巴**叠加回开头**，
  所以第一拍听到的是「上一轮余响 + 本轮起音」。

`test-bgm.mjs` 里有一条断言专门查这个：任何音符的 `t + d` 越过循环长度就报错，
因为折回时会被硬切，听感上是一个突兀的断音。

在页面里用 `<audio loop>` 直接循环即可，不需要额外的交叉淡化处理。

## 重新生成

```bash
npm install          # 首次需要，会装 lamejs（纯 JS 的 MP3 编码器）
npm run gen:bgm      # 重新生成全部曲目
node tools/gen-bgm.mjs liushui    # 只生成某一首
```

脚本是幂等的：每次都会完整覆盖 `public/bgm/*.mp3`，并清理格式不符的残留文件。
中间产物 `.wav` 写在 `.cache/bgm/` 下，**不会**进入 `public/`，也不会被打包。

## 编码参数

**11025 Hz / 56 kbps 单声道。** 这两个数字不是随便选的：

- 11025 Hz 的奈奎斯特频率是 5512 Hz。这些曲子的谐波本来就在 5.5 kHz 以下
  （最亮的马林巴和闭镲也就到那一带），降采样率没有可听损失，体积却只有 44.1 kHz 的 1/4；
- 56 kbps 是 MPEG-2 Layer III 在 11025 Hz 下的**倒数第二档**
  （可选 8/16/24/32/40/48/56/64）。想设 96 kbps 是物理上不存在的——
  lamejs 会静默地降到 64，看起来「设了没生效」。

`test-bgm.mjs` 会读 MP3 帧头校验版本位，防止有人「顺手」把采样率调回 44.1 kHz
——那会让整包体积涨到 30 MB 以上。

## 实现结构

```
tools/
├── gen-bgm.mjs          主流程：乐谱 → MIDI → 合成 → MP3
└── lib/
    ├── theory.mjs       音名 / 频率 / 音阶 / 和弦 / 可复现随机数
    ├── songs.mjs        全部曲目的编曲（唯一需要改音乐的地方）
    ├── midi.mjs         MIDI 写入（SMF Format 1，含速度、拍号、标记）
    ├── midi-read.mjs    MIDI 读回（合成器真正读的是解析出来的音符）
    └── synth.mjs        合成器：振荡器 / ADSR / 滤波 / FM / 混响 / 延迟
```

几个刻意的设计：

- **MIDI 不是导出产物，而是中间格式。** 乐谱先写成 `.mid`，再解析回来交给合成器，
  所以 `.mid` 和 `.mp3` 必然一致，不会出现「导出的 MIDI 和听到的不是一首」。
- **相位累加器而不是 `Math.sin(f * i)`。** 后者在几十万个样本后浮点误差累积，
  会产生沙沙的颗粒感。
- **每个单发音符的缓冲区末尾都有 6 ms 淡出。** 否则音符在衰减到零之前被截断，
  会有「哒」的爆音。
- **只在真的超过 0 dBFS 时才做 `tanh` 软限幅**，否则纯线性归一到 −3 dBFS，
  避免无谓的失真。
