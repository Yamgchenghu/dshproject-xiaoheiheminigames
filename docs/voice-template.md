# 朗读模板

抽完之后念什么，由**模板**决定，默认 `抽到{result}`。

## 为什么是模板

用户想要的念法差别很大：

- 只想听结果：`{result}`
- 想听"第几次抽"：`抽到{result}，第{count}次`
- 要报时间：`{time}抽到{result}`
- 只想听数值：`{value}`

写死任何一种都会有人不满意。模板只多一个输入框，却能覆盖所有念法。

## 占位符

| 占位符 | 含义 | 示例 |
|---|---|---|
| `{result}` | 选项的完整文本 | 火锅 |
| `{value}` | 选项的**数值**字段，没填就用文本 | 5 |
| `{count}` | 这个选项被抽中的次数（含本次） | 3 |
| `{last}` | 本转盘还没抽过的选项数 | 5 |
| `{time}` | 当前时间，UTC+8 | 11月15日09时30分 |
| `{total}` | 本转盘的选项总数（不含禁用） | 8 |

规则：

- **未知占位符原样保留**。写错成 `{中奖}` 会照原样念出来，一眼就能看出没被识别，
  比静默替换成空字符串好排查。
- **空模板等于默认值** `抽到{result}`，不会念出空字符串。
- **`{value}` 没填时退回文本**。否则设了模板却没设数值会念出"抽到"，听起来像卡住了。
- `{time}` 固定 UTC+8，不用设备本地时区——同一份存档在不同设备上要念出同一个时间。

## 选项的数值字段

选项文本和要念的数值经常不是一回事：

| 文本 | 数值 | 念出来 |
|---|---|---|
| 一等奖 | 一 | 抽到一 |
| +5 分 | 五 | 抽到五 |
| 谢谢参与 | （空） | 抽到谢谢参与 |

在「选项」页每行的「数值」按钮里填。留空就是"没设过"。

**为什么不自动从文本里抠数字**：文本里的数字形态太多（罗马数字、中文数字、
带单位），自动抠出来十次有八次是错的，而且用户没法纠正。

数值**不影响抽奖概率**，只影响朗读。概率由「权重」决定。

## 界面

设置页 → 朗读开关打开 → 出现「朗读模板」卡片：

- 输入框，实时保存（改完不用点保存）
- 六个占位符按钮，点一下插到光标处
- 实时预览：「预览：抽到火锅」
- 每个占位符的说明

## 和原 APK 的关系

原 APK 的 `core.js` 里是：

```js
const tpl = db.settings.ttsTemplate || '抽到 {result}';
```

支持 `{result}` `{count}` `{last}` `{time}` `{total}`。本项目的模板语义与之一致，
额外加了 `{value}`。原 APK 没有数值字段，所以导入它的包时 `value` 都是空，
`{value}` 会自动退回文本。

## 导出兼容性

`value` 会写进「完整版 ZIP 2.0」的 items 里。原 APK 不认识这个字段，
解析时会直接忽略，**不会破坏兼容性**。
## 持久化

模板存两份：

| 位置 | 作用 |
|---|---|
| 本地 `wheel:cfg:v1` | 即时保存，每次改都写，无成本 |
| 云存档 `wheel:cfg:cloud:v1` | 副本，换手机/重装能恢复 |

读取时**以本地为准**，本地没有（新设备、清过数据）才读云端并写回本地。
云存档写入失败不影响本地保存，不会让用户以为没存上。

## 导出

「完整版 ZIP 2.0」的 `settings` 里带 `ttsTemplate`，字段名和原 APK 一致：

```json
{
  "app": "yunhai-wheel",
  "version": 2,
  "settings": {
    "autoGoto": true,
    "avoidReset": 0,
    "defaultAvoid": false,
    "ttsTemplate": "抽到 {result}"
  },
  "wheels": [ ... ]
}
```

- **导出**：`settings.ttsTemplate` 写的是当前模板；模板为空则不写这个键（保持原包结构）
- **导入**：读 `settings.ttsTemplate` 恢复模板；**只在备份里有值时才覆盖**，
  否则导入一个不含设置的旧包会把用户调好的模板冲掉
- 原 APK 读这个字段是 `db.settings.ttsTemplate`，**完全兼容**——两边的包可以互导

「仅数据 JSON」和「仅数据 PWH」两种格式不带设置，它们的目标是给别的工具读选项列表。
